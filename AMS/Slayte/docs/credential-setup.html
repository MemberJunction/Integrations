Connect Slayte to MemberJunction

Read-only AMS integration for Individuals & Organizations (via Shared CRM Queries), Committees, Directories, and Events over Slayte API v2.

1. Create API Key(s) in Slayte

As a Slayte Superadmin, open Admin > API in your Slayte workspace and create an API key pinned to API version 2026-10-01 (or newer).

Grant read scopes for the surfaces you plan to sync:

  • crm:query — required to list and execute Shared CRM Queries for bulk Individual and Organization sync
  • crm:read — required for single-record Individual/Organization lookups and Relationship Definitions
  • committees:read — required for Committees, Positions, Terms, and Committee Members
  • events:read — required for Events, Sessions, Speakers, Companies, Registrations, Registrants, and Guests
  • directory:read — required for Directories and Directory Entries
If your workspace separates crm:query onto its own API key, enter that key in the optional CRM Query API Key (QueryApiKey) field; otherwise leave it blank to reuse the primary ApiKey.

2. Configure the Slayte API Credential

FieldRequiredDescription
SiteUrlYesYour workspace root URL, e.g. https://your-site.slayte.com
ApiKeyYesPrimary Slayte API key sent in the X-Api-Key header
QueryApiKeyNoOptional separate API key with crm:query scope for /v2/crm/query/*

3. Configure Shared CRM Query IDs (Individuals & Organizations)

Slayte API v2 bulk-exports Individuals and Organizations through Shared CRM Queries. Ensure each query includes the UUID column (individualUuid or organizationUuid), then set the query UUIDs in CompanyIntegration.Configuration:

{
  "individualQueryId": "00000000-0000-0000-0000-000000000000",
  "organizationQueryId": "00000000-0000-0000-0000-000000000000",
  "individualQueryParams": {},
  "organizationQueryParams": {}
}

Tip: sync the CRMQuery object first (or call GET /api/v2/crm/query?entityType=ind and org) to discover available Shared CRM Query UUIDs and parameter UUIDs in your workspace.
