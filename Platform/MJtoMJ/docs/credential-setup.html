Before you start

This connects to another MemberJunction instance — the source — and copies its Conversations and Conversation Details (the individual messages) into this deployment. It only ever reads from the source; it never writes back.

You'll gather two values from that source instance and send them to us: its GraphQL endpoint URL and a read-only API key. Both come from the source instance's MemberJunction administrator — the person who runs it. Nothing to install.

  1. 1

    Get the source instance's GraphQL endpoint URL

    Ask the administrator of the MemberJunction instance you want to pull from for its GraphQL API URL — the address this deployment will call to read data. It's normally that instance's host with /graphql on the end, for example https://mj.your-org.org/graphql. One thing to confirm: the URL must be reachable from this deployment. If the source instance lives only inside a private network, let us know so we can arrange access.

  2. 2

    Get a read-only API key from the source instance

    The same administrator provides a read-only API key for that instance. It comes from the instance's app configuration / server settings — specifically the API key value its MemberJunction API server validates requests against. This is the same regardless of whether that instance's database runs on SQL Server or PostgreSQL. If the source instance issues scoped or per-application keys, ask for a read-only one rather than a full-access key.

  3. 3

    Confirm the key can read conversations

    Before sending it over, have the administrator confirm the key is authorized to read Conversations and Conversation Details on the source instance. That's all this connector touches. If the key is scoped down, those two areas need to be included in its read access — otherwise the sync will connect but come back empty.

You're done

Treat the API key like a password. It grants read access to the source instance's data, so share it only with us and only over a secure channel — not plain email or chat if you can avoid it. Prefer a read-only or scoped key over a full-access one, and remember it can be revoked on the source instance at any time if you ever need to cut off access.
