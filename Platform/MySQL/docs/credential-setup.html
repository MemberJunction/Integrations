Connection setup

Connect your MySQL database

Give MemberJunction a read-only login to your MySQL database so we can sync your data. A database administrator can set this up in about ten minutes.

Read-only 6 values to send ~10 minutes

Before you start

You'll need someone with administrator access to your MySQL server — this works for MySQL, MariaDB, and Amazon Aurora (MySQL). The steps below create a dedicated, read-only login and open network access to it. When you're done you'll send us six values: your host, port, database name, username, password, and whether SSL is enabled.

  1. 1

    Gather your connection details

    First, note down how MemberJunction will reach your database. Your database administrator or hosting provider will have these:

    • Host — the server's address, e.g. db.yourcompany.com or an IP like 10.0.4.20. For a cloud database this is the endpoint from your provider's console (for example an Amazon RDS/Aurora endpoint).
    • Port — the port MySQL listens on. The default is 3306; only change it if your server was set up differently.
    • Database name — the specific database (schema) you want us to read, e.g. production. You can confirm the list with SHOW DATABASES;.
  2. 2

    Create a read-only user

    Log in with an admin account (via the MySQL command line or a tool like MySQL Workbench, DBeaver, or phpMyAdmin) and run the SQL below. Replace <strong-password> with a strong, unique password and <your_database> with the database name from Step 1.

    -- Create a dedicated login MemberJunction will use (read-only).
-- '%' lets it connect from any host; see Step 3 to lock this down.
CREATE USER 'mj_readonly'@'%' IDENTIFIED BY '<strong-password>';

-- Grant SELECT (read) on the database you want us to sync.
GRANT SELECT ON `<your_database>`.* TO 'mj_readonly'@'%';

-- Apply the changes.
FLUSH PRIVILEGES;

    Why read-only? GRANT SELECT lets us read your data but never change or delete it. Please don't grant INSERT, UPDATE, DELETE, or admin privileges — they aren't needed.

  3. 3

    Allow network access

    MemberJunction connects to your database over the network, so the server must accept connections from us. Depending on how your database is hosted, that usually means one or more of:

    • Server binding — make sure MySQL isn't limited to local-only connections. In my.cnf the bind-address should allow remote hosts (not just 127.0.0.1). Your admin can confirm this.
    • Firewall / security group — open inbound port 3306 (or your custom port) to MemberJunction. For a cloud database (RDS/Aurora, Cloud SQL, Azure) this is an inbound rule on the security group or firewall.
    • Allowed host — the user in Step 2 was created with '%' (any host). To tighten it, we can give you a specific IP address to allow instead — just ask, and replace '%' with that address.
  4. 4

    Enable SSL (recommended)

    Whenever the database is reachable over the public internet, we require an encrypted (TLS/SSL) connection — for any non-local host, MemberJunction refuses to connect over plaintext. Most managed databases (RDS, Aurora, Cloud SQL, Azure Database for MySQL) have SSL enabled by default. If you self-host, ask your admin to confirm the server has TLS configured. Then just tell us SSL is enabled in the handoff below and we'll connect securely.

Keep the password safe. The login you created is read-only, so it can never change your data — but anyone with the password can read it. Send the password to us only over a secure channel, separate from the other values where you can. You can revoke our access at any time by running DROP USER 'mj_readonly'@'%'; on your server.
