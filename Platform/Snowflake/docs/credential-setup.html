Connection setup

Connect your Snowflake account

A quick, read-only connection so MemberJunction can sync your data — we only ever read, and never change anything in your warehouse. About five minutes, with help from whoever administers your Snowflake account.

Read-only 7 values to send ~5 minutes

Before you start

You'll need someone who administers Snowflake (an ACCOUNTADMIN, or a role that can create roles and users) and the ability to run a few lines of SQL in a Snowsight worksheet. When you're done you'll have seven values to send us: your connection details plus a dedicated read-only login. Nothing here changes your data — the login we ask you to create can only read. (A Role is only needed if you use one; if not, you'll simply omit it and send six.)

  1. 1

    Gather your connection details

    Collect the details that tell us where to connect: your Account identifier, the Warehouse we should run queries on, the Database and Schema you want us to sync from, and the Role if your account uses one.

    The account identifier is the part before .snowflakecomputing.com in your login URL — for example xy12345.us-east-1 (legacy locator, region included) or myorg-myaccount (organization-account form). You can find it in Snowsight: open the account selector at the lower-left and choose View account details, or go to Admin → Accounts — the Account URL shown there contains it. If your account uses the legacy locator, be sure the region (e.g. us-east-1) is included as part of the identifier.

  2. 2

    Create a read-only role and user

    Please give us a dedicated login that cannot modify anything — strongly recommended over sharing an existing account. Run the following in a Snowsight worksheet as an administrator, choosing your own password and substituting your warehouse for <wh>, database for <db>, and schema for <schema>:

    CREATE ROLE mj_readonly;

GRANT USAGE ON WAREHOUSE <wh>                 TO ROLE mj_readonly;
GRANT USAGE ON DATABASE  <db>                 TO ROLE mj_readonly;
GRANT USAGE ON SCHEMA    <db>.<schema>        TO ROLE mj_readonly;
GRANT SELECT ON ALL    TABLES IN SCHEMA <db>.<schema> TO ROLE mj_readonly;
GRANT SELECT ON FUTURE TABLES IN SCHEMA <db>.<schema> TO ROLE mj_readonly;

CREATE USER mj_readonly PASSWORD='choose-a-strong-password' DEFAULT_ROLE=mj_readonly;
GRANT ROLE mj_readonly TO USER mj_readonly;

    This creates a role named mj_readonly that can read the tables in your schema but not change them, and a user of the same name that logs in with it. The FUTURE TABLES grant ensures it can also read any tables added later. You can name the role and user anything you like — just send us the name and password you chose. If your data spans more than one schema, repeat the three schema-level grants for each.

  3. 3

    Allow network access

    If your account restricts logins with a Network Policy or IP allowlist, MemberJunction's servers need to be permitted. We'll give you the exact IP address(es) to add to your ALLOWED_IP_LIST (or your network rule) — just let us know this step applies to you. If you don't use a network policy, there's nothing to do here.

  4. 4

    Connections are always encrypted

    There's no SSL setting to configure — Snowflake accepts connections only over TLS, so the connection between MemberJunction and your account is always encrypted in transit. Nothing for you to send for this step.

You're done
