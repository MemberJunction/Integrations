Connection setup

Connect your PostgreSQL database

A quick, read-only connection so MemberJunction can sync your data — we only ever read, and never change anything in your database. About five minutes, with help from whoever manages it.

Read-only 6 values to send ~5 minutes

Before you start

You'll need whoever administers the database (a DBA, or access to your hosting provider's dashboard) and the ability to run a few lines of SQL. When you're done you'll have six values to send us: your connection details plus a dedicated read-only login. Nothing here changes your data — the login we ask you to create can only read.

  1. 1

    Gather your connection details

    Collect three things that tell us where the database lives: the Host (the server's address or hostname, e.g. db.internal.example.com), the Port (PostgreSQL uses 5432 by default), and the Database name you want us to sync from. If you're on a managed host (Supabase, Neon, Amazon RDS/Aurora, Azure), these are shown on your database's connection or overview page.

  2. 2

    Create a read-only database user

    Please give us a dedicated login that cannot modify anything — strongly recommended over sharing an existing account. Run the following in your database as an administrator, choosing your own password and substituting your database name for <db>:

    CREATE ROLE mj_readonly LOGIN PASSWORD 'choose-a-strong-password';
GRANT CONNECT ON DATABASE <db> TO mj_readonly;
GRANT USAGE ON SCHEMA public TO mj_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO mj_readonly;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT ON TABLES TO mj_readonly;

    This creates a login named mj_readonly that can read your tables but not change them. The final line ensures it can also read any tables added later. You can name the role anything you like — just send us the name and password you chose. If your data lives in schemas other than public, repeat the two public grants for each schema.

  3. 3

    Allow network access

    MemberJunction connects to your database over the network, so it needs to be reachable from our servers. Depending on where the database runs, that may mean opening a firewall rule, adding an entry to pg_hba.conf, or allow-listing our IP in your cloud security group. We'll give you the exact IP address(es) to allow — just let us know this step applies to you.

  4. 4

    Confirm SSL

    If the database is reachable over the public internet, we strongly recommend requiring SSL/TLS so the connection is encrypted in transit. Most managed hosts (Supabase, Neon, RDS, Azure) enforce it by default. Check whether your server requires SSL and simply tell us yes or no in the handoff below.

You're done
