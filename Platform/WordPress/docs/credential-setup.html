Connect your WordPress site

Create an Application Password in your WordPress profile and send us three values. About five minutes — no developer needed.

Application Password 3 values to send ~5 minutes

Before you start

You'll need an Administrator account on your WordPress site, and the site must be served over HTTPS. When you're done you'll send us three values: your site address, your username, and an Application Password you create below.

Your site must be on HTTPS. WordPress hides the Application Passwords section entirely on sites served over plain http:// — this is core behaviour, not something we can work around. If you don't see the section in step 2, this is almost always why.

  1. 1

    Open your profile

    Sign in to wp-admin and go to Users → Profile (or Users → All Users and click the account you want the integration to use). We recommend a dedicated user for the integration rather than a personal login, so access can be revoked without disrupting anyone.

  2. 2

    Scroll to Application Passwords

    Scroll to the bottom of the profile page to the Application Passwords section. If it isn't there, your site is either not on HTTPS (see the note above) or a security plugin has disabled the feature.

  3. 3

    Name it and add it

    Type a name you'll recognise later — MemberJunction works well — then click Add New Application Password. The name is only a label; it doesn't affect access.

  4. 4

    Copy the password now

    WordPress shows the password once, as six blocks of four characters (for example abcd EFGH 1234 ijkl MNOP 5678). Copy it before you leave the page — it cannot be shown again, only replaced. The spaces are part of it; leave them in.

Optional — only if you want activity-log data

If you'd like us to sync your WP Activity Log history (who logged in, what changed, when), that data lives in the plugin's own database tables and isn't reachable over the WordPress API on its own. We supply a small read-only companion plugin that exposes it.

Install mj-wsal-bridge into wp-content/plugins/ and activate it under Plugins. It adds no settings screen, writes nothing, and sends nothing anywhere on its own. Skip this step and everything else still works — the activity-log tables simply stay empty.

Note that we can only read what the plugin has kept: WP Activity Log prunes history on a default of three months, and anything already pruned is gone for good.

Optional — WooCommerce

The Application Password above already covers WooCommerce. You only need WooCommerce API keys if you'd prefer to give us access to store data alone, without the rest of the site. In that case generate a Read key under WooCommerce → Settings → Advanced → REST API and send the Consumer key and Consumer secret instead.

A WooCommerce-only key cannot read posts, pages, users or media — those objects will be reported as unavailable rather than silently syncing nothing.

Send the site address exactly as you'd type it in a browser, including https://. If your site lives in a subfolder, include that too — for example https://yoursite.org/blog.

Treat the Application Password like a password. With your username it grants the same access that account has, so share it only with us over a secure channel. You can revoke it at any time from the same Application Passwords section — revoking affects only the integration, never your own login.
