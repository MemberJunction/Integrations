Connection setup

Connect your SharePoint sites

Register a read-only application in your Microsoft tenant and send us the three values it produces. About fifteen minutes for a Microsoft 365 administrator.

Microsoft 365 admin required 3 values to send ~15 minutes

Before you start

You'll need a Microsoft 365 administrator — registering an application and granting it consent are both admin actions. One of the three values is shown only once, so have somewhere safe to paste it before you start.

Step 1 · Open the Microsoft Entra admin centre

https://entra.microsoft.com

Sign in as an administrator and open Applications → App registrations. Entra ID is the service that used to be called Azure Active Directory — if you land in the Azure portal instead, the same pages are under Microsoft Entra ID.

  1. 2

    Register the application

    Choose New registration, name it something recognisable such as MemberJunction Sync, and leave it as single tenant. No redirect URI is needed — this application never signs a person in.

    Choose Register.

  2. 3

    Copy the two IDs from the Overview page

    The application's Overview page shows an Application (client) ID and a Directory (tenant) ID. Copy both — neither is secret, and both are always available here if you need them again.

  3. 4

    Create a client secret

    Open Certificates & secrets → Client secrets → New client secret. Give it a description and an expiry that suits your organisation's policy.

    Copy the Value column immediately — it is shown only once, and the Secret ID next to it is not the value we need.

  4. 5

    Grant read-only permissions

    Open API permissions → Add a permission → Microsoft Graph → Application permissions and add Sites.Read.All and Files.Read.All. Add User.Read.All as well if you want user records synced.

    Choose Application permissions, not Delegated — the sync runs on its own, with no person signed in.

    Then choose Grant admin consent. Every permission must show a green tick before the connection will work.

If you missed the secret value

It genuinely cannot be shown again. Delete that secret and create another one — the application registration, its IDs and its permissions are all unaffected.

You're done

Send us these 3 values

00000000-0000-0000-0000-000000000000 Microsoft
00000000-0000-0000-0000-000000000000 Microsoft
•••••••••••••••••••••••• secret

Treat the client secret like a password. The permissions you granted in Step 5 are what bound it — read-only Graph scopes mean it can read the SharePoint content you consented to and nothing else. Send it only to us and only over a secure channel, and note its expiry date so the connection can be refreshed before it lapses.
