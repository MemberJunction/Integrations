NetForum: one record that xWeb cannot write as XML no longer stops a read or removes the object's joined columns.

- **The fault.** A value with a control character (for example 0x02) makes xWeb answer GetQuery with HTTP 500: `' ', hexadecimal value 0x02, is an invalid character.` Every read faults on the page that holds the record. On a live tenant, a full read of `Individual` stopped at page 138 of about 280 on every try.
- **Not a verdict on the column list.** The fault taught nothing, so the connector marked the object's full column list `unsendable` in `.nf-learned.json`. From the next run, the object was read with its own-table columns only, without any joined column. This fault is now never learned against the list.
- **Read around the record.** On this fault, the connector finds the first record of the page that xWeb cannot write. It sends the same request with a smaller `@TOP` (a binary search, about log2 of the page size requests). xWeb joins only the tables a list names, so one record can span several rows of the list, and the row after the largest readable page belongs to the record on its last row or to the next record. The connector checks each of the two with the same request narrowed to its key (`<key> = '…'`); the next record's key comes from a request that names only the key and the WHERE clause's columns. It returns the readable rows of the other records, warns `RECORD_UNREADABLE` with the record's key, and the next page starts after that key. When the record cannot be located, the error says why.
- **The read ends incomplete.** When the read reaches its last page, the next call throws an error that lists the skipped keys, so the engine holds the watermark and does not treat a skipped record as deleted. Remove the character from the listed records in netFORUM.
- **Fault cost.** xWeb locks the account at about 100 faults a day. A request that draws this fault is no longer sent again (other HTTP 5xx answers are still retried 3 times), so it costs 1 fault, not 4. The search and the key checks run under a new daily probe budget, `unreadable` (20 faults per connection per UTC day, kept in `.nf-learned.json` with the other probe counts). A read skips at most 5 records and does not search for a sixth. When the budget or the limit stops a read, the error says so and lists the records skipped so far.
- **Upgrade note.** An object that this fault already marked `unsendable` stays on its own-table list until its entry is removed from `.nf-learned.json`.
